# RTX 3090 host PLE storage probe — 2026-09-15

No model or server was started.  All measurements read the production
`ple.f8_e4m3.bin` through a read-only ext4 mount.

## Raw NVMe random-read probe

Command:

```bash
python3 tools/nvme_probe.py \
  --file /mnt/ai_models/Qwen3.8-Flash-Next-int2-mixed-AutoRound-24GB-SGLang/ple/ple.f8_e4m3.bin \
  --reads 4000 --tokens 1024
```

The probe uses 4 KiB `O_DIRECT` reads, bypassing the page cache.

| Queue depth | IOPS | p50 us | p99 us | MB/s |
|---:|---:|---:|---:|---:|
| 1 | 2,993 | 276 | 819 | 12.3 |
| 4 | 13,520 | 243 | 801 | 55.4 |
| 16 | 54,471 | 269 | 685 | 223.1 |
| 32 | 55,583 | 517 | 1,004 | 227.7 |
| 64 | 4,406 | 863 | 837,620 | 18.0 |

QD16-32 is the useful range.  QD64 collapses on this virtualized storage path.

## PLE access replay

`tools/ple_io_bench.py` compares the production NumPy mmap gather with
deduplicated 16-worker `pread` calls over identical row IDs.  Each trial is
1024 tokens x 16 PLE heads = 16,384 row lookups.  The tool checks every output
byte with BLAKE2 rather than relying on timing alone.

| Unique rows | Cold mmap ms | Warm mmap ms | Dedup pread ms | Cold winner |
|---:|---:|---:|---:|---|
| 256 | 23.8 | 2.2 | 41.0 | mmap |
| 512 | 28.6 | 2.3 | 47.0 | mmap |
| 1,024 | 41.8 | 2.2 | 36.5 | approximately tied |
| 2,048 | 72.7 | 1.3 | 47.2 | pread |
| 4,013 | 877.1 | 2.3 | 74.8 | pread |
| 7,052 | 863.9 | 2.0 | 147.5 | pread |
| 16,384 | 3,661.5 | 2.7 | 330.4 | pread |

The cold mmap timings vary with kernel cache eviction and the virtual block
device, so the 2,048-row switching threshold is provisional.  The conclusion
is nevertheless strong at high entropy: mmap exposes roughly QD1 page-fault
behavior, while parallel pread is about 11x faster for a fully unique chunk.
For the benchmark's repeated sentence, the small n-gram working set strongly
favors warm mmap.

## Implemented experiment

- `patches/ple_bulk_pread.py` adds an opt-in hybrid gather.  It deduplicates IDs
  on CPU, retains mmap below 2,048 unique rows, and uses the existing 16-worker
  pool above the threshold.
- `patches/enable_ple_bulk_pread.py` enables it in `/root/quant/serve-3090.sh`
  for the next manual server start.  Both the feature and threshold remain
  environment-overridable.
- Apply/compile/revert was checked in memory, and the source/launcher patch
  states were checked after application.  End-to-end validation is pending
  because model execution was explicitly excluded.
