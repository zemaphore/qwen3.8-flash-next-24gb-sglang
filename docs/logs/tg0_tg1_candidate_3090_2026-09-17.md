(boot 2 was +2.5–6 % over boot 1), and the candidate boot 1 matches the

(control: 29.91 tok/s, 64 MiB). This is the one notable TG0 difference — the
main port runs nearer the memory edge at the capacity limit. It is a single
smoke, not a statistical result, and was recorded after the full 128K matrix;
it warrants a repeat before any claim.

## TG1 — presence vs pooled-mass placement at fixed S184

Assets: `expert_presence_code.pt` (launcher default; the code-presence asset
consumed through its `mass` field, as the served code does) vs `expert_freq.pt`
(the three-domain routing histogram from the original probe). Both arms load
the asset with the same code path and report the same effective placement
(`48 layers at S=184`). Bracketed across boots: presence, mass, mass, presence.

Full-matrix boots (n=5), presence − mass:

| Workload | presence | mass | delta |
|---|---:|---:|---:|
| prose 2K | 38.11 | 29.78 | **+28.0 %** |
| reasoning 2K | 38.23 | 26.96 | **+41.8 %** |
| code 2K | 35.46 | 21.22 | **+67.1 %** |
| code 32K | 31.75 | 27.57 | +15.1 % |
| prose 32K | 36.55 | 32.97 | +10.8 % |
| reasoning 32K | 37.48 | 31.89 | +17.5 % |
| reasoning 128K | 29.55 | 26.04 | +13.5 % |
| code 128K | 29.33 | 26.89 | +9.1 % |
| prose 128K | 27.90 | 27.16 | +2.7 % |

Second-boot short cells (n=3), presence − mass: prose 2K +3.4 %, reasoning 2K
+13.8 %, code 2K +23.5 %.

The pooled-mass placement is slower in every cell on both boots, and the effect
is largest at short context on the code class. The control conditions argue this
is a host-read wait, not throttling: temperature (73–79 °C), SM clock
(1,870–1,913 MHz) and free-VRAM minima are equivalent across arms, while the
mass arm draws **less** power (219–257 W vs 258–274 W) — the GPU waits rather
than computes. The two assets' top-184 sets overlap only ~131/184 per layer, so
they are materially different placements.

The magnitude exceeds the ~8–15 % the TG plan anticipated and is larger than the
control's boot-to-boot noise, but the mass asset is explicitly workload-specific
(built from a different three-domain probe); this is a measured TG-only result
on the TG0 corpora. **PP was not measured**, so this is not a full TG1
tradeoff, and no default was changed — presence remains the launcher default.

## Limitations

- Both arms are single-box, single-profile measurements; the TG1 mass arm has
  high SD at 2K (up to ±3.75 tok/s) and the pair is only bracketed over two
  boots each.
- The capacity smoke difference is one observation.
- The profile is the TG0 control (no radix, 256K), not the currently promoted
  230K radix profile; the promoted profile's TG was separately probed
  (~29.8 tok/s at 28.9K, trace 12/12) during the migration validation.
- Clocks were not pinned; power/thermal state was only sampled.
