# PP5b — PP11 + prefill-presence placement interaction: ACCEPTED

Date: 2026-09-15. Host: RTX 3090. Stack: accepted PP11 batched host-row DMA
staging on top of PP7, 2,048-token chunks, S184 residency, bulk PLE pread plus
the 128 MiB recent-row cache, 2,048-byte gather tile. Only the canonical code
benchmark was used; no repeated-sentence benchmark or `llama-benchy` was run.

## Result

Accepted by the owner. Prefill-presence placement takes the accepted PP11 stack
from pooled mass controls of **1177.3 +/- 26.1** to **1244.0 +/- 25.3 PP
tok/s**: **+5.67%**. The pooled gain clears the campaign's 5% gate; against the
bracketing control A alone it is +4.94% and against control B +6.40%. Every one
of the five presence samples (minimum 1214) exceeded every one of the ten mass
samples (maximum 1211), and a two-sample t-test gives t = 4.76, so the
separation is well outside run-to-run noise, but the single-control delta is
exactly at the gate edge; the owner adopted it on the pooled, predeclared
bracketing method.

`assets/expert_presence_code.pt` is now the launcher default. Routing mass
(`assets/expert_freq.pt`) remains selectable with
`SGLANG_MOE_PLACEMENT=$ASSETS/expert_freq.pt`.

## Exactness

On the presence server:

```text
m4_3090_untuned: LOGPROB_MAX=0.000000 LOGPROB_MEAN=0.000000
lp2:             LOGPROB_MAX=0.168757 LOGPROB_MEAN=0.011632
```

Both are identical to PP1b/PP2a/PP3/PP4/PP7/PP11. Placement only changes which
rows are resident versus staged on the host; PP7 stages identical bytes per
expert and the fused kernel is untouched, so the change is exact by
construction and the oracles confirm it.

## Caveat

The presence placement is derived from the canonical code prompt's routing
(nine chunks: six M=2048 plus three M=469 via `tools/pp5_presence.py`), so the
gain is workload-specific in a way the general-domain mass histogram is not.
The accepted metric is that canonical code workload, and the two oracle checks
are unaffected either way. If a materially different workload mix replaces the
code benchmark as the primary target, re-derive the placement before assuming
the gain transfers.
