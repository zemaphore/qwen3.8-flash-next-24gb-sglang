# PP11 batched host-row DMA — RTX 3090, 2026-09-15

## Result

Accepted. `cudaMemcpyBatchAsync` replaces one Python `Tensor.copy_` submission
per cold row with one CUDA submission per staged tensor kind. The PP7 unique
expert set, resident/host partition, staging layout, byte count, and fused-MoE
inputs are unchanged.

The deterministic 4,565-token code benchmark improved from a pooled bracketing
control of **1110.9 +/- 26.7** to **1183.4 +/- 18.3 PP tok/s** (mean and sample
SD): **+6.53%**. Against the immediately following control alone the change is
1101.8 -> 1183.4 tok/s, **+7.41%**. Both exactness oracles are unchanged.

## Change under test

- Source layer: `patches/moe_host_dma_batch.py`, applied after PP7.
- Launcher layer: `patches/enable_moe_host_dma_batch.py`.
- Only A/B variable: `SGLANG_MOE_GATHER_DMA_BATCH=1` versus `0`.
- A dedicated non-legacy CUDA stream is required because the batch API rejects
  the legacy NULL stream. One bridge on each side of a layer permits resident
  row gathers to overlap host DMA while preserving dependencies.

## Model-free sizing

`tools/pp11_batch_copy_bench.py` copied 258 production-sized 819,200-byte rows
(211.4 MB decimal) for seven repetitions:

| Submission path | GPU time | Effective bandwidth | CPU submit time |

## Code-only E2E A/B

Every sample used `tools/bench_agentic.py --tokens 4096 --decode-tokens 256`.
The first request after each restart is excluded; the following five are
measured.

All requests completed without CUDA, allocator, retraction, or server errors.
Post-suite free VRAM was 3,235 MiB. Server output is
`/root/quant/logs/server.log` (overwritten on restart); the scope ids identify
the journal records.
