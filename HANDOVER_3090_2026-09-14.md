## What M4 changed

Elastic expert streaming compacts each prefill layer to the experts selected by
that layer and request. `E` at the fused-MoE call is consequently dynamic rather
than the checkpoint's fixed 512. The original 3090 server log produced requests
from roughly E=60 through E=437; weighted quantiles were p10/p25/p50/p75/p90 =
117/186/285/342/379. Exact config filenames alone could not cover that space.

M4 adds six measured RTX 3090 expert-count buckets—128, 192, 288, 352, 384 and
432—with separate gate/up and down-projection files. Each file contains M=128,
512 and 1024 entries. They live under:

```text
assets/moe_configs/configs/triton_3_7_1/
  E=<bucket>,N=160,device_name=NVIDIA_GeForce_RTX_3090,dtype=int2_w2a16.json
  E=<bucket>,N=160,device_name=NVIDIA_GeForce_RTX_3090,dtype=int2_w2a16_down.json
```

`tools/tune_moe_int2.py` is a purpose-built tuner for the patched symmetric INT2
N-contiguous layout. It exercises the real production `fused_experts_impl` path,
allows the two projections to use different configs, verifies outputs, and keeps
a candidate only when it beats the fallback by at least 1%. The final run covered
18 `(E,M)` points: all 18 passed, individual speedups were 1.011-1.977x, and the
geometric mean was 1.380x. All harness comparisons were bit-identical. Full traces
and selected configs are in `docs/logs/m4_int2_tuning.json`.

`patches/moe_config_buckets.py` patches SGLang's config resolver. Exact lookup
still wins; with `SGLANG_MOE_CONFIG_NEAREST_E=1`, a missing dynamic E selects the
nearest file only when Triton version, device, N, dtype and projection suffix all
match. The patch is installed in `/root/sglang`. Apply or inspect it with:

```bash
SGLANG=/root/sglang python3 patches/moe_config_buckets.py --check
SGLANG=/root/sglang python3 patches/moe_config_buckets.py apply
```

`/root/quant/serve-3090.sh` now defaults the flag on while permitting an A/B:

```bash
SGLANG_MOE_CONFIG_NEAREST_E="${SGLANG_MOE_CONFIG_NEAREST_E:-1}"
# control launch:
SGLANG_MOE_CONFIG_NEAREST_E=0 /root/quant/serve-3090.sh
```

The standalone `sglang/qwen4exp-serving-73a255206f.patch` remains the base serving
patch. M4 is an additional layer represented by `patches/moe_config_buckets.py`
and the new assets; it has not been folded into that large flat patch.

## Validation and interpretation

The machine-local oracle was recorded on the untuned 3090 server as
`tools/logprob/m4_3090_untuned.json`. The tuned server matched all 450 forced
tokens exactly:

```text
LOGPROB_MAX=0.000000 LOGPROB_MEAN=0.000000
```

The older cross-state `lp2` reference gave max 0.1688 / mean 0.01163. Its slight
mean-threshold miss is not caused by M4: the controlled same-machine A/B is exact.

The repository's original speed tool repeats one short sentence, which is an easy
expert-routing workload. Its warmed result still gives a stable regression check:

| Context | Untuned PP tok/s | M4 PP tok/s | Delta |
|---:|---:|---:|---:|
| 101 | 171 | 180 | +5.3% |
| 421 | 388 | 398 | +2.6% |
| 1,701 | 618 | 739 | +19.6% |
| 6,821 | 788 | 821 | +4.2% |
| 10,001 | 814 | 847 | +4.1% |

The complete output is `docs/logs/m4_bench_3090.txt`.

`llama-benchy --pp 2048 --depth 2048` concatenates 2,048 prompt tokens and
2,048 previous-context tokens when prefix caching is disabled, so its PP rate is
for about 4,096 varied-corpus tokens. Isolated one-run A/B was 222.8 -> 243.6
tok/s, which overstated the stable gain. The three-run comparison was:

```text
                    PP tok/s          TG tok/s
untuned       226.21 +/- 7.38   37.18 +/- 0.98
M4           230.17 +/- 3.61   39.71 +/- 1.25
delta                    +1.8%              +6.8%
```

The PP result is positive but inside the run-to-run spread. Decode M <= 16 uses
the separate expert-GEMV path, so the TG difference must not be attributed to
the M4 config files.

For coding-agent work, `tools/bench_agentic.py` sends a deterministic review
instruction plus the real serving patch. The 4,565-token request showed that
resident-expert state dominates one-off latency on this offload setup:

| State | PP tok/s |
|---|---:|
| Untuned cold samples | 256-278 |
| M4 cold sample | 269 |
| Untuned after the identical prompt warms the expert cache | 457 |
| M4 after the identical prompt warms the expert cache | 461, 447 |

M4 is inside the warmed code-workload variance. The large cold/warm spread explains
why repeated-text measurements look far faster than natural prose or code. M4 makes
the fused INT2 calculation faster after weights arrive; host-to-GPU expert traffic
is now the larger target for coding-agent prefill.

## Open work, in priority order

1. **Reduce coding-workload expert transfer.** Profile the elastic gather/copy
   separately from fused MoE compute. Explore overlap of pinned-host copies with
   layer compute, and retune `expert_freq.pt` from representative code and agent
   traces. The current placement histogram came from only 2,496 tokens across
   three general domains. Re-evaluate the S=184 resident-expert budget if VRAM
   measurements allow it.
2. **Parameterize the PLE decode thread pool.** The custom mmap embedding hard-codes
   `ThreadPoolExecutor(max_workers=16)` for gathers of at most 64 rows. SGLang's GPU
   model runner already calls `torch.set_num_threads(1)`, so generic
   `OMP_NUM_THREADS` is not equivalent to llama.cpp's thread knob. Add an env-backed
   PLE worker count and sweep 4/6/8/16; measure TG, API TTFT and CPU scheduling.
   Also test `RAYON_NUM_THREADS=4,6` for Hugging Face tokenization and systemd
   `CPUAffinity`, one variable at a time.
3. **Tune with real route skew.** The tuner uses synthetic routing while forcing all
   compact experts to appear. Add route-ID replay from coding requests so config
   selection reflects the skew and per-expert token counts seen in agent work.
4. **Keep realistic benchmarks.** Use at least three `llama-benchy` runs and the
   deterministic code prompt. Treat `tools/bench_speed.py` as a repeatable smoke
   regression test, not an absolute agentic-prefill number.
5. **Portability.** Fold the nearest-E resolver into the reviewable SGLang patch or
   upstream series once its interface is settled. Until then, a fresh SGLang checkout
   needs both the base flat patch and `patches/moe_config_buckets.py apply`.
